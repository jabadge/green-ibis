# Using uv with this repository

[uv](https://docs.astral.sh/uv/) is a tool that installs Python and Python packages. In this
repository it replaces `pip`, `conda` and `python -m venv`: one command builds an environment
with exactly the package versions everyone else is using, and another runs your script
inside it.

You do not need to install Python or any packages yourself first. uv handles both.

## The three files uv uses

| File | What it is | Tracked by git? |
|---|---|---|
| `pyproject.toml` | The list of packages the project needs, written by hand. | yes |
| `uv.lock` | The exact version of every package, generated by uv from `pyproject.toml`. This is what makes everyone's environment identical. Never edit it by hand. | yes |
| `.venv/` | The environment itself: a folder holding Python and the installed packages. Built by uv on your machine. Safe to delete, since uv can rebuild it. | no |

## 1. Install uv

You do this once per machine.

**macOS or Linux**
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```
On macOS with Homebrew, `brew install uv` also works.

**Windows (PowerShell)**
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Open a new terminal and check that it worked:
```bash
uv --version
```

## 2. Build the project environment

From the repository root (the folder containing `pyproject.toml`):
```bash
cd green-ibis
uv sync --extra shapefile --extra interactive
```

This creates `.venv/` and installs the versions recorded in `uv.lock`. If you have no
suitable Python (3.10 or newer), uv downloads one. The first run takes a minute or two.
Later runs take seconds.

The `--extra` flags add optional groups of packages on top of the core ones:

| Extra | Needed for |
|---|---|
| `interactive` | the Jupyter notebooks and interactive ROI drawing |
| `shapefile` | building flowlines from shapefiles (`src/flowline/flowline_shp.py`) |
| `lazy` | lazy and cloud reads of observations (`src/data_io/obs_lazy.py`) |

To install everything, use `uv sync --all-extras`.

> **`uv sync` makes the environment match exactly what you ask for.** Running it later with
> fewer `--extra` flags *removes* the packages from the extras you left out. Use the same
> flags every time.

## 3. Run a Python script

Put `uv run` in front of the command you would normally type:
```bash
PYTHONPATH=src uv run python examples/example_sverdrups_workflow.py
```

`uv run` runs the command with the project's `.venv/`. You do not need to activate
anything. Run it from the repository root or any folder below it.

`PYTHONPATH=src` is specific to this repository. The code in `src/` is not installed as a
package, so this tells Python where to find it and lets you write imports such as
`from data_io.obs_netcdf import load_obs_netcdf`. On Windows PowerShell, set it on its own
line first:
```powershell
$env:PYTHONPATH = "src"
uv run python examples/example_sverdrups_workflow.py
```

Other things you can run the same way:
```bash
PYTHONPATH=src uv run python                                    # interactive Python prompt
PYTHONPATH=src uv run python -m config.config                   # show the configured data paths
uv run python tests/compare/test_variance_synthetic.py          # a test
uv run jupyter lab notebooks/                                   # notebooks (needs the interactive extra)
```
The scripts in `examples/`, `tests/` and `notebooks/` add `src/` to the path themselves, so
`PYTHONPATH=src` is optional for those. Your own scripts need it.

> **`uv run` also syncs before it runs,** using the core packages only. That would remove the
> extras you installed in step 2. To prevent this, either repeat the flags
> (`uv run --extra shapefile --extra interactive python ...`) or tell it to use the
> environment as it is (`uv run --no-sync python ...`).

### If you prefer to activate the environment

`.venv/` is an ordinary Python virtual environment, so the traditional way also works:
```bash
source .venv/bin/activate        # Windows: .venv\Scripts\activate
export PYTHONPATH=src
python examples/example_sverdrups_workflow.py
deactivate                       # when you are done
```
To use it in VS Code or another editor, select `.venv/bin/python` as the interpreter.

## 4. Stay up to date

After a `git pull` that changes `pyproject.toml` or `uv.lock`, run the sync command from
step 2 again. It installs only what changed.

## 5. Add or change a package

```bash
uv add netCDF4                        # add to the core dependencies
uv add --optional lazy s3fs           # add to an extra (here, "lazy")
uv remove netCDF4                     # remove
uv lock --upgrade-package xarray      # move one package to its newest allowed version
```

Each of these updates `pyproject.toml`, `uv.lock` and your `.venv/` together. Commit both
`pyproject.toml` and `uv.lock` so that everyone else gets the change.

Do not use `pip install` inside the environment. Packages installed that way are not
recorded in `uv.lock`, nobody else gets them, and the next `uv sync` removes them.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `uv: command not found` | Open a new terminal. If it still fails, the installer printed a folder to add to your `PATH`. |
| `ModuleNotFoundError` for a repository module (`data_io`, `roi`, `compare`, ...) | `PYTHONPATH=src` is missing, or you are not in the repository root. |
| `ModuleNotFoundError` for `geopandas`, `ipympl`, `dask`, ... | The package belongs to an extra that is not installed. Rerun step 2 with the right `--extra`, and see the note on `uv run` in step 3. |
| Warning that `VIRTUAL_ENV=...` does not match the project environment | Another environment is active in your terminal. uv ignores it and uses `.venv/`, so the warning is harmless. Run `deactivate` to silence it. |
| The environment seems broken | Delete `.venv/` and rerun step 2. |
| Error that the lockfile needs to be updated | `pyproject.toml` was edited by hand. Run `uv lock`, then commit the new `uv.lock`. |

## Command summary

| Task | Command |
|---|---|
| Build or update the environment | `uv sync --extra shapefile --extra interactive` |
| Run a script | `PYTHONPATH=src uv run --no-sync python path/to/script.py` |
| Start Jupyter | `uv run --no-sync jupyter lab notebooks/` |
| Add a package | `uv add <package>` |
| Update uv itself | `uv self update` (or `brew upgrade uv`) |

Full documentation: <https://docs.astral.sh/uv/>
